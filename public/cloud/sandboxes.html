01

What a sandbox is

A private, temporary computer for one agent or one task, isolated from everything else.

02

Why AI agents need sandboxes

Agents run code they wrote themselves; a sandbox contains mistakes before they reach real systems.

03

Run an agent inside a sandbox

Give each agent its own files, tools and terminal to work in safely.

04

Copy a full app for testing

Spin up a complete copy of your application without touching production.

05

Run untrusted code safely

Execute code you did not write, with no path to your data or credentials.

06

Test with synthetic patient data

Every healthcare sandbox starts with realistic sample records, never real ones.

07

The isolation model

Separate filesystem, network and credentials for every sandbox.

08

Snapshots and fast starts

Start from a saved, ready-to-go setup in seconds.

09

Saving work between sessions

Agents can pick up their files and state where they left off.

10

Live logs and errors

Watch output stream as it happens.

11

Scale to thousands of sandboxes

Stay reliable when demand spikes.

12

Pay only while running

Idle sandboxes stop automatically, so you never pay for idle compute.

13

Limited-permission keys

Each API key can do only what you allow.

14

Internet blocked by default

Allow only the addresses a task actually needs.

15

Secrets kept out of reach

The platform supplies credentials so agent code never sees them.

16

The sandbox audit trail

Every command is recorded, kept and exportable for review.
